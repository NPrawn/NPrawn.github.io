02 / Engineering

개발 과정에서 중요하게 생각한 것

기술을 사용했다는 사실보다, 해당 기술을 선택한 이유와 경계 상황을 다룬 경험을 보여줍니다.

ASYNCHRONOUS PROCESSING

긴 작업과 API 요청의 분리

AutoQuant에서 장시간 계산을 RabbitMQ와 별도 Worker로 분리했습니다. 큐 대기·계산·저장 시간을 구간별로 계측하고, Worker 수와 DB 연결 수를 조정해 실행 시간뿐 아니라 전체 시스템의 자원 경쟁도 함께 고려했습니다.

CONSISTENCY & RECOVERY

데이터 정합성과 복구 가능성

백테스트 실행 기록과 Outbox를 동일 트랜잭션에 저장해 메시지 발행 실패에 대응했습니다. 데이터베이스 제약조건과 상태 전이 검증으로 중복 실행·중복 저장 같은 경계 상황을 방어했습니다.

REAL-TIME RELIABILITY

연결 이후의 상태까지 관리

PinGo에서 WebRTC Signaling의 참여자 인증, room 수명주기, 재접속, 늦게 도착한 종료 이벤트 처리에 참여했습니다. 정상 연결뿐 아니라 취소·종료·네트워크 단절 이후에도 서비스 상태가 일관되도록 설계했습니다.
